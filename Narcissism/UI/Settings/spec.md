# Subsystem Spec: Settings Window

## Metadata

- **Title**: The Settings window with toolbar-style tab pages.
- **Surface**: a standard titled window, shown from the menu's "Settings..." item.
- **Actor isolation**: main-actor.
- **Related code**: `Narcissism/SRSettings.swift` (every control binds a preference); `Narcissism/UI/Menu/spec.md` (owner and entry point); `Narcissism/Posture/spec.md` (the nudge settings this window edits); `Narcissism/UI/Statistics/spec.md` (the statistics window that briefly lived here as a tab); `VISION.md` next to this file (the long-term plan).

## Summary

- **What this subsystem is**: the app's one configuration window: a normal `NSWindow` whose content is an `NSTabViewController` in toolbar style (the System Settings look), with a General page, a Posture page, and a Notifications page.
- **One-sentence contract**: every control reflects its bound preference live and writes it back on change; the window has no side effects beyond preferences and the calibration funnel.

## Scope

- **In scope**: `SRSettingsWindowController` (window + tabs), `SRSettingsGeneralViewController`, `SRSettingsPostureViewController`, `SRSettingsNotificationsViewController`, and the two-way binding controls in `SRSettingsControls.swift` (`SRPreferenceSwitch`, `SRPreferenceCheckbox`).
- **Constraints / assumptions**:
  - Shown via the About-window recipe (`makeKeyAndOrderFront` plus `NSApp.activate`) plus `orderFrontRegardless`, never by changing the activation policy - that stays owned by the Dock tile controller. The regardless-ordering matters: with the Dock tile off the policy is `.prohibited`, activation is refused, and without it the window opens behind the active app. It is a one-time jump to the front, not a floating level; other windows cover it normally afterwards.
  - Placement (the app-wide rule for summoned windows, defined here and referenced by Statistics, About, Welcome, and Posture): the first open centers on the interaction screen - the one holding the pointer at the menu click (`NSScreen.interaction` in `UI/SRWindowPlacement.swift`) - never `NSScreen.main`, which for a menu-bar agent with no key window falls back to the primary display and opened the window on the wrong screen when docked. Placement is decided once, at presentation: the kept instance means a reopen shows the window where the user left it, and an open window is never moved by the app. The calibration window is the one deliberate exception - it follows its camera's display (Posture/spec.md).
  - No page attaches to the camera session yet; the window consumes nothing from `SRCameraService`.

## Responsibilities and ownership

- **Responsibilities**:
  - General page: Track Posture switch, Show Camera Panel switch (`cameraPanelPinned`), Show Camera in Menu Bar switch (`showCameraOnStatusBar`), Prefer External Display Camera switch (`preferExternalCamera`, default on: while Automatic, a monitor's camera takes over the built-in when docked - see `Narcissism/Tools/spec.md`), Open at Login switch (`launchAtLogin`).
  - Posture page: one shared label axis for the whole page (the classic pref-pane form), split into two groups by a full-width separator rule. Every row's label right-aligns to a single colon column; values and controls sit in the control column after it. The calibration group up top: the baseline status line for the camera in use ("Calibrated <date>" from that camera's `PostureBaselines` entry, or "Not calibrated" when it has none; it follows both a recalibration and a camera switch. A third "Partially calibrated <date>" state existed from 2026-08-03 to 2026-08-10, for an entry with no usable slouch span; calibrated is binary again now that the span is gone, see `Narcissism/Posture/spec.md`), and directly under it the Calibrate Posture button in the control column (a labelless cell, the way a form's action button rides under its values; enabled only while tracking is on, routed through the owner's calibration funnel). Then the rule, then the strictness group - a "Tracking strictness" section header (leading, semibold) over the two strictness sliders. Calibration reads first because it defines the baseline the strictness is measured against; the rule keeps the baseline and its button together rather than stranding the button below the sliders. Only the strictness group carries a header: the calibration group is self-evident from its baseline line and button, while the bare sliders do not say what the strictness governs, so the header names it. The rule carries a group-sized gap above and below (about twice the 10pt row spacing) so the two groups read as separate; the rows themselves keep the 10pt rhythm the General and Notifications tabs use, so page density stays aligned across tabs.
  - The strictness sliders (`SRPreferenceStepSlider`, a two-way binding control like the switch and checkbox) are tick-marked five-stop ladders, relaxed on the left: `PostureSlouchStrictnessIndex` (which stop of the ladder, 0...4, default 2 - the stop's meaning in percent below baseline is set per camera regime, see `Narcissism/Posture/spec.md`) and `PostureShoulderTolerance` (12/10/8/6/4 percent tilt slope, default 10, the tolerance value itself). Each row is named for its metric alone (Slouch, Shoulder tilt) so the label fits the pane; the "Tracking strictness" header above carries the strictness framing, and the ends are labeled (Relaxed / Strict), the System Settings tick-slider convention. An off-ladder stored value selects the nearest stop. "Tracking", not "Notification", because these thresholds define what counts as bad posture - for the nudges and the recorded statistics alike (see `Narcissism/Posture/spec.md`) - not just when a nudge fires. They live here rather than on Notifications for the same reason. Always enabled: configuration of intent, like everything on this window.
  - Notifications page: the nudge delay popup (5 s / 10 s / 30 s / 1 m / 5 m writing `PostureNudgeDelaySeconds`; an off-list stored value selects the closest step), the three channel checkboxes (corner note, sound, status-item tint) stacked under a single "Notify with" label with each channel's own sub-option nested one indent beneath it, so the dependency reads spatially rather than by a repeated label: the note's ghost-mode checkbox ("Fade under the pointer", `PostureNoteGhost`; enabled only while the note channel is on) sits under the note, the sound picker (bare, no repeated "Sound" label; enabled only while the sound channel is on; selecting persists the name and plays it once as a preview) sits under the sound, and the status-item tint has no sub-option. The "Notify with" label baseline-aligns to the first checkbox. and, set apart above by a full-width separator rule (the same group-sized gap the Posture tab uses, because Snooze is a temporary pause rather than delivery configuration), the snooze popup, rebuilt on every deadline change to mirror the menu's states: idle it shows "Off" over the durations; while snoozed it shows an inert "Until <time>" state line, the durations, and an explicit Resume Now item, so turning a snooze off is always one visible choice away. The popup is enabled only while Track Posture is on, because with tracking off the composition root clears any snooze write immediately (the master toggle means a clean slate).
  - The window title follows the selected tab, like System Settings; each page sets its own preferredContentSize, so the window resizes per tab, also like System Settings. All pages share one width (540) for horizontal stability; height is each page's fitting height with no floor, so a page hugs its content instead of padding out to a fixed minimum (the per-tab resize is the toolbar-preference convention, and content-fit keeps a sparse tab from showing dead space below its rows).
  - Home-window experiment, tried and reversed (2026-07-28, same day): the window was briefly the app-named home window - Statistics tab first, one fixed page size, opened at launch on Statistics, title no longer following the tab. Reversed to keep the app a quiet menu-bar agent: no main window, nothing opens at launch except the first-run welcome. Statistics moved to its own window (`Narcissism/UI/Statistics/spec.md`); this window went back to being purely Settings.
- **Owned invariants**:
  - Controls bind to raw preferences; camera availability is deliberately not consulted here. This page configures intent; the surfaces themselves explain an unavailable camera. (The menu makes the opposite choice and gates on availability; both are recorded decisions.)
  - A preference change made anywhere else (menu, hotkey) updates the visible control live, and vice versa - the menu and this window can be open at once and never disagree.
  - `SRMenuController` owns the single instance (the About precedent) and keeps it across closes, so the window and its selected tab survive reopening.
  - The Calibrate button behaves exactly like the menu's Calibrate item: clear any snooze, then the one shared calibration funnel, so a second calibration window can never appear.

## Requirements

- **Native fidelity**: real `NSTabViewController` toolbar tabs, SF Symbol tab icons, `NSSwitch`/checkbox/popup system controls; window `toolbarStyle` is `.preference`.
- **Concurrency**: main-actor throughout; bindings ride the preference publishers.
